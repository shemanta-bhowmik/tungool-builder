## Workflow rules (non-negotiable)
1. Work in small steps. One task = one block or one clearly scoped change.
2. After code changes run `npm run build` (and `composer dump-autoload` if PHP classes were added/renamed). Fix all build errors before reporting.
3. NEVER claim something "works". Report "built successfully, ready for your visual check" and list exactly what I should test in the editor and on the frontend. A block is only marked done in docs/roadmap.md after I confirm visually.
4. When fixing styling issues, prefer CSS-only fixes. Do not change block markup, attributes or InnerBlocks structure unless necessary — and if you must, say why first. Changing saved markup/attributes can break existing content.
5. Never edit files in `blocks/build/`, `assets/build/`, `vendor/` or `node_modules/` by hand.
6. List every file you created/changed at the end of each task. Suggest a git commit message.
7. Ask before deleting files, renaming attributes of a finished block, or adding npm/composer dependencies.

## Architecture in one paragraph
Thin bootstrap file → Composer PSR-4 autoload (`includes/`) → `Plugin::instance()->init()` (Singleton trait)
→ modules loaded on `plugins_loaded`. `App\BlockHandler` registers every block from
`blocks/build/blocks-manifest.php` (generated by `wp-scripts --blocks-manifest`). All blocks are DYNAMIC:
`block.json` + `index.js` + `edit.js` + `render.php` (no save.js; container blocks with InnerBlocks
use `save: () => <InnerBlocks.Content />`). Shared editor controls live in `blocks/src/shared/` and are imported by blocks.

## Hard coding rules
- block.json: apiVersion 3, `$schema`, category = plugin slug (custom category), textdomain set, real dashicon/SVG icon, `example` filled.
- Only reference files in block.json that exist (no `viewScript` unless view.js exists).
- Attribute types must match their defaults and what controls save (number ↔ number).
- edit.js: always spread `useBlockProps({ className: '...' })` — never override `className` after spreading.
- render.php: ALWAYS output the wrapper with `get_block_wrapper_attributes()` (once, no duplicate class attr). Escape late: esc_html / esc_attr / esc_url; RichText content via `wp_kses_post`. Balanced markup in every branch.
- No inline global `<style>` per block. Instance styles go through the uniqueId + DynamicCSS pipeline (see architecture.md).
- All user-facing strings translated with `__()` / `esc_html__()` using the text domain.
- PHP: `if ( ! defined( 'ABSPATH' ) ) exit;` at top of every PHP file. WordPress Coding Standards.
- JS: `@wordpress/*` packages only (no React import, no jQuery in blocks). Prefer core controls/hooks.
- Use theme palette via `useSettings('color.palette')` — never hardcoded color lists.
